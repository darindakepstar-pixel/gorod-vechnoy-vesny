
# Город вечной весны — прототип

Визуальная новелла. Работает в браузере на телефоне и на компьютере.

## Файлы

| Файл | Что это |
|---|---|
| `scenes.js` | **Весь текст игры.** Правишь только его, когда пишешь сюжет. |
| `engine.js` | Движок: печать текста, выборы, счётчики, сохранения. Трогать не нужно. |
| `index.html` | Разметка и оформление. |
| `config.js` | Ключи Supabase. Пока заглушки — игра работает локально. |
| `cloud.js` | Связь с Supabase: аккаунты, сохранения, статистика. |
| `supabase.sql` | Схема базы. Выполнить один раз в Supabase. |
| `check_art.html` | Проверка, все ли картинки на месте. |
| `check.js` | Проверка сюжета на битые ссылки. |
| `art_prompts.md` | Готовые промпты для генерации картинок. |
| `art/` | Сюда кладёшь картинки. Имена файлов — в `art/README.txt`. |

## Как запустить локально

Просто открой `index.html` двойным кликом. Всё.

## Как выложить для подруг

1. Создай репозиторий на GitHub, залей туда все файлы.
2. Settings → Pages → Source: `main`, папка `/ (root)`.
3. Через минуту ссылка вида `https://твойник.github.io/имя-репо/` — её и рассылай.
4. На телефоне «Добавить на главный экран» — откроется как приложение.

## Как включить аккаунты и общую статистику

Пока ключи не заполнены, игра работает локально: сохранения лежат на устройстве,
на титуле написано «локальный режим». Чтобы появились аккаунты, шесть шагов.

**1. Создай проект в Supabase.** Регион бери поближе — Сингапур или Токио.

**2. Заведи таблицы.** SQL Editor → New query → вставь содержимое `supabase.sql` → Run.
Скрипт можно запускать повторно, ничего не сломается.

**3. Выключи подтверждение почты.** Authentication → Sign In / Providers → Email →
сними галочку **Confirm email** → Save.

Это обязательный шаг. Игроки входят по имени и паролю, никакой настоящей почты у них
нет — движок делает технический адрес из ника. Если подтверждение включено, Supabase
будет ждать письма, которое никуда не придёт, и вход не сработает.

**4. Возьми ключи.** Project Settings → API. Нужны **Project URL** и ключ
**anon public**. Ключ `service_role` не трогай, он даёт полный доступ к базе.

**5. Впиши их в `config.js`:**

```js
supabaseUrl: 'https://твойпроект.supabase.co',
supabaseKey: 'eyJhbGci...',
```

Ключ `anon` можно спокойно держать в коде — он для этого и предназначен, а доступ
к данным ограничен правилами в базе: каждый видит и правит только своё сохранение.

**6. Проверь.** Открой игру. На титуле должно появиться «облако подключено» и поля
для входа. Создай аккаунт, пройди пару сцен, закрой вкладку и зайди снова с другого
устройства под тем же именем — игра должна продолжиться с того же места.

### Что даёт аккаунт

Игрок при входе видит карточку: на какой главе остановился, сколько сцен прочитано
из общего числа, сколько времени в игре, сколько концовок найдено, когда играл
в последний раз. Плюс кнопка «Кто как далеко» — общий список всех игроков.

Счётчики симпатии в общий список намеренно не попадают: иначе подруги увидят чужие
ветки раньше, чем пройдут свои.

### Где смотреть статистику самой

Table Editor → представление `progress`. Там видно, кто на какой главе застрял.
Если половина игроков остановилась на одной и той же сцене — значит, в этом месте
текст провисает, и это повод его переписать.

## Как писать новые сцены

Открой `scenes.js`, скопируй любую сцену, поменяй `id`, текст и `next`.
Обычная сцена:

```js
ch3_01: { bg:'city', who:'ТАНК', sprite:{char:'tank', emo:'happy'},
  text:'Ты вообще ела сегодня?', next:'ch3_02' },
```

Сцена с выбором (тогда `next` не нужен):

```js
ch3_05: { bg:'city', text:'Он ждёт ответа.',
  choices:[
    { text:'Согласиться.', love:{tank:2}, next:'ch3_06a' },
    { text:'Отказаться.',  love:{tank:-1}, flags:['отказ'], next:'ch3_06b' },
  ]},
```

Доступные фоны и персонажи перечислены вверху `scenes.js`.
После правок запусти `node check.js` — покажет опечатки в ссылках между сценами.

## Отладка

Клавиша `D` на компьютере или кнопка в меню — показывает счётчики симпатии,
текущую сцену и накопленные флаги. Перед раздачей подругам просто не жми её.

## Управление

- Клик или тап по тексту — дальше. Во время печати — домотать реплику.
- Пробел / Enter на компьютере — то же самое.
- «Лог» — всё прочитанное. «Меню» — сохранения и скорость текста.

## Картинки

Клади в папку `art/` с именами вида `lei_neutral.png` и `bg_airport.jpg`.
Игра подхватывает их сама, код менять не нужно. Пока файла нет — на его месте
цветная заглушка, так что вставлять можно по одной.

Промпты для генерации — в `art_prompts.md`.

## Чего пока нет

Мини-игры, создание персонажа, комната, музыка, генератор обложки, главы 3–7.
Всё это навешивается на готовое ядро.

## Как работают статы и симпатия

В игре два вида очков, и они устроены по-разному.

**Симпатия** (лэй / танк / шэнь) — скрытая. Игрок её не видит. Она копится
от выборов и в конце третьей главы решает, чью ветку откроет игра. Плюс внутри
ветки её порог влияет на концовку.

**Статы** (китайский, деньги, репутация) — видны в углу экрана. Влияют двумя способами:

1. **Открывают выборы.** У варианта в сцене может стоять `require:{rep:8}` —
   тогда он показан, но заблокирован с подписью «нужно: репутация 8+», пока
   игрок не накопит. Так высокая репутация или знание языка открывают реплики,
   недоступные тем, кто шёл иначе.

2. **Ветвят сцену сами, без кнопки.** У сцены может стоять
   `route:[{require:{lang:6}, next:'...'}]` — если у игрока хватает стата,
   игра уходит в особую сцену автоматически. Так в лапшичной героиня понимает
   китайскую перепалку, только если учила язык.

3. **Решают концовку.** В конце ветки Лэя `route` по симпатии и репутации
   выбирает один из трёх финалов: лучший, хороший или горький.

### Как добавить порог в сцену

Заблокированный выбор:
```js
{ text:'Ответить на их языке.', require:{lang:5}, love:{shen:2}, next:'...' }
```

Автоматическая ветка по стату (ставится ДО choices/next):
```js
route:[{ require:{rep:10}, next:'особая_сцена' }],
```

Порог концовки — тот же route в предпоследней сцене ветки.
